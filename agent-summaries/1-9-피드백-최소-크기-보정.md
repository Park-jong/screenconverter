# 1-9 피드백: 최소 크기 보정 (feedback-synthesizer 보고, 메인 에이전트가 대신 저장)

## 판정: 완료. 1′(창 구조 변경) 항목을 닫아도 되며 추가 루프 불필요
- 1-6 권고(상수 대신 계산, 캡처 영역 최소 320x180, 초기 640x360 유지, 장식 변경 금지) 모두 충족.
- 실측(배율 1.0): 최소 창 518x221, 그때 CapturePanel 내부 320x180. SE/NW 대각 축소, 최대화→복원, `setSize`/`setBounds` 강제 모두 같은 최소로 클램프. 초기 내부 442x319. 테스트 6개 통과. 닫기 4가지 종료 코드 0.
- 1-7 보고의 예상값 518x229는 세로 +8 가정 오류. 실제 518x221(180 + 라인 border 2 + 제목줄·테두리 39)이며 코드는 맞음.
- `onShown()` 순서: `applyMinimumSize` → `shownHook` → `updateCaptureRect` → `startCapture`.
- 한계: captureRect 일치는 정적 좌표 비교(픽셀 비교는 2-3에서 완료).

## 3단계 진입 시 사실 모음
- **창 구조**: 장식된 JFrame 하나 = HWND 하나(제목줄·테두리·CapturePanel·MenuPanel). WDA_EXCLUDEFROMCAPTURE는 HWND 단위라 모두 한 번에 제외되며 정상. 장식 변경·dispose 후 재표시 금지(HWND 변경 시 affinity 소실). `setMinimumSize`는 안전. 최소 창 518x221, 최소 캡처 영역 320x180, 초기 640x360(내부 442x319), 배율 1.0·단일 모니터 기준.
- **5px 둥근 모서리**: 3단계 합격 판정에 섞지 말 것. 겹침 비교에서 좌하단 5픽셀 예외는 3단계 실패가 아니라 기존 이월 항목으로 구분.
- **코드 구조**: 캡처 호출 지점은 `captureOnce` 한 곳("stage 3 hide/exclude point" 주석). captureRect는 volatile·EDT에서만 쓰기. 주기 33ms, `RobotScreenGrabber`(createScreenCapture 기반), `ScreenGrabber` 인터페이스로 교체 용이. 현재는 자기 창을 찍는 무한 반복 상태이며 3단계가 해소해야 함. `closeApp()`: shutdownNow → dispose → System.exit(0), 종료 시 affinity 복구 불필요.
- **구현 지침**: `win32` 패키지에 `DisplayAffinity` 인터페이스(`boolean excludeFromCapture(Component)`) + JNA 구현체 한 파일. JNA 5.14.0, `Native.getComponentPointer(window)` → `WinDef.HWND`(null이면 실패). `SetWindowDisplayAffinity` 0x11 설정 후 `GetWindowDisplayAffinity`로 되읽기, 실패 시 GetLastError 기록, UnsatisfiedLinkError·비 Windows는 catch해 false. 0x11은 Win10 2004+ (현재 Win11 26200).
- **핵심 불확실성**: Robot(GDI BitBlt 계열)이 0x11 창을 제외하는지 한 번도 실측하지 않음. 제외되면 검은색이 아니라 뒤쪽 실제 화면이 나와야 함(WDA_MONITOR 0x1은 검게 나옴). 캡처 루프 가동 상태의 동적 비교도 첫 기회.
- **검증 방법**: 2-2의 패턴 JFrame 하네스 재사용, 투명도 0 래핑 제거하고 순수 RobotScreenGrabber 사용. 겹침 영역 전수 비교 bad=0, 오버레이 내부색 (40,40,40)·테두리색 (200,200,200) 불검출. affinity 미적용(FAIL)/적용(PASS) 양성·음성 대조. 이동·리사이즈 후, 최소·최대화 상태 유지 확인(1-8 Robot 리사이즈 하네스 합쳐 사용). `java -jar` 종료 코드 0·stderr 비어 있음·java 프로세스 잔존 0.
- **대체안(Robot이 제외를 따르지 않을 때)**: ① 캡처 순간에만 창 숨기기(`captureOnce` 한 곳, 깜빡임 크면 완료 기준 미달) ② Windows Graphics Capture / DXGI Desktop Duplication(비용 큼, 마지막 수단).
- 3단계 완료 시 갱신: `captureOnce` 주석, ROADMAP 진행표, 위험도 표. DPI·다중 모니터를 하지 못하면 보고에 명시.
