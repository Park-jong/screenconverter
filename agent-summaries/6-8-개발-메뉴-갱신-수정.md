# 6-8 개발: 메뉴 갱신 문제 수정 (code-writer 보고, 메인 에이전트가 대신 저장)

배경: 창 폭을 마우스 드래그로 넓히면(시작 폭 640 기준 약 800px 이상) 메뉴 칸 상태는 정상인데 화면의 메뉴가 갱신되지 않는 문제(조사 문서 `창-폭-확대-후-메뉴-상태-오류-조사.md`). 조사에서 `-Dswing.bufferPerWindow=true`로 해결 확인. 사용자 지시("1번으로 수정")로 최소 변경만 수행하고 개발 후 멈춤.

`mvn -B package` BUILD SUCCESS, 테스트 175개 통과(기존 173 + 신규 2). 스모크 `java -jar target\converter.jar` 약 5초: 계측 꺼진 상태에서 stdout·stderr 0바이트, 예외 없음, 자기가 띄운 프로세스(PID 24348)만 `converter.jar` 명령줄로 찾아 종료(다른 java 프로세스는 건드리지 않음). 리뷰 판정 없음, `ROADMAP.md` 미수정(메인이 처리).

## 변경 파일
- `src/main/java/com/converter/Main.java`: 패키지 전용 정적 메서드 `configureRendering()` 추가 — 프로퍼티가 `null`일 때만 `swing.bufferPerWindow=true`로 설정하므로 사용자가 `-D`로 준 값은 덮어쓰지 않음, 이유와 조사 문서 이름을 주석에 적음. `main()`의 첫 줄에서 `configureRendering()` 호출.
- `src/test/java/com/converter/MainTest.java`(신규): 프로퍼티가 없을 때 `true`로 설정되는지, 이미 `false`로 지정돼 있으면 유지되는지(두 테스트 모두 끝나면 프로퍼티를 원래 값으로 복원).

## 클래스 로드 순서
`Main`에는 AWT/Swing 정적 필드나 정적 초기화 블록이 없고, `OverlayWindow` 등은 `invokeLater` 람다 안에서만 참조되어 프로퍼티 설정 뒤에 로드됨. `Main`의 import에 `SwingUtilities`가 있어도 `main`이 실제로 쓰는 시점은 `configureRendering()` 다음.

## 하지 않은 것·확인하지 못한 것 (검증 단계로 넘김)
- 창 폭을 넓혔을 때 메뉴가 실제로 갱신되는지(드래그 시험, Robot 자동화, 스크린샷 비교), 성능 측정(CPU·그리기 속도 영향), 회귀 시험.
- 실행 중인 JVM에서 프로퍼티가 실제로 적용됐는지(단위 테스트로만 확인).
