# 2-1 개발: 화면 캡처 (code-writer 보고, 메인 에이전트가 대신 저장)

`mvn -B package` BUILD SUCCESS, 테스트 10개 통과(기존 ResizeLogicTest 7 + 신규 CaptureRegionTest 3). `java -jar` 5초 실행 시 stderr 0바이트, 프로세스 유지, 이후 taskkill로 종료(java 프로세스 0개). 종료 코드 0, 1:1 일치, 이동·리사이즈 중 갱신, CPU 사용량은 개발 단계에서 미확인.

## 신규 파일
- `capture/ScreenGrabber.java`: `BufferedImage grab(Rectangle)`. 빈 영역·실패 시 null.
- `capture/RobotScreenGrabber.java`: Robot을 생성자에서 한 번만 생성해 재사용. null/폭·높이 0 이하면 null.
- `capture/CaptureRegion.java`: 순수 로직 `inner(screenX, screenY, w, h, Insets)`. insets를 뺀 내부 사각형, 비면 null.
- `ui/CapturePanel.java`: JPanel 상속. volatile BufferedImage + `setImage()`(저장 후 repaint). `paintComponent`는 super 먼저, 이미지 없으면 기존 배경색, 이미지는 `drawImage(img, in.left, in.top, w, h, null)`로 insets 안쪽에 그림. 캡처 없음.
- `test/.../CaptureRegionTest.java`: 3개 테스트.

## 수정 파일
- `OverlayWindow.java`: content를 CapturePanel로 교체(마우스 리스너·커서·ESC·우클릭 유지). 캡처 사각형은 EDT에서 `content.getLocationOnScreen()` + `CaptureRegion.inner`로 계산해 `volatile Rectangle captureRect`에 값 복사(ComponentListener moved/resized, `onShown()`에서 갱신). 단일 스레드 `ScheduledExecutorService`(데몬 "capture-worker", `scheduleWithFixedDelay(0, 33ms)`)가 `captureRect`를 복사해 grab 후 `invokeLater`로 `setImage`. 캡처 호출 지점은 `captureOnce` 한 곳(예외는 잡아서 출력). `closeApp()`에서 `shutdownNow()` 후 dispose, System.exit(0). 3단계 훅: `setShownHook(Runnable)` + `onShown()`(훅 실행 → 사각형 갱신 → 캡처 시작). JNA 호출 없음.
- `Main.java`: `setVisible(true)` 직후 `window.onShown()` 호출.

자기 창이 찍히는 무한 반복은 요청대로 그대로 둠(3단계에서 해결).
