## 2단계 진입 시 주의점
- **구조**: JPanel 상속 `CapturePanel`을 만들어 `paintComponent`에서 그리고 OverlayWindow의 content 타입을 교체한다. 마우스 리스너·커서는 이 패널에 그대로 둔다(겹치는 새 패널 금지). 테두리는 `getInsets()` 기준, 하드코딩 금지.
- **좌표**: 캡처 대상은 패널 내부(insets 제외) 영역의 화면 좌표. 이미지는 (insets.left, insets.top)부터 그려 1px 어긋남이 없게 한다. 폭/높이 0 이하 방어 코드. 창이 화면 밖으로 나가면 검은색일 수 있으나 이 단계에서는 문제 아님.
- **DPI**: 반환 이미지 크기가 요청 사각형과 다를 수 있으니 `drawImage(img, x, y, w, h, null)`로 대상 크기를 명시. 본격 대응은 5단계.
- **그리기**: `paintComponent`에서는 캡처하지 않고 마지막 이미지(`volatile BufferedImage`)만 그린다. `super.paintComponent` 먼저, 이미지 없을 때 배경색 폴백 유지.
- **스레드**: 별도 단일 스레드(`ScheduledExecutorService.scheduleWithFixedDelay`, 약 30~60ms)에서 Robot 캡처(Robot은 한 번만 생성), 결과는 `invokeLater`로 EDT에 전달해 저장 후 `repaint()`. 캡처 사각형은 EDT에서 읽어 값 복사 후 워커로 넘긴다. 종료 시 `shutdownNow()`, 데몬 스레드.
- **무한 반복은 이 단계에서 정상**이며 고치지 않는다(3단계 일).
- **3단계 대비**: 캡처를 `ScreenGrabber`(Rectangle → BufferedImage) 같은 작은 인터페이스로 분리해 구현체만 교체 가능하게 한다. 창 숨기기 대체안의 호출 지점은 캡처 워커 한 곳에 모은다. HWND는 displayable 이후에만 얻을 수 있으므로 창을 띄운 직후 호출할 훅을 남긴다. JNA 의존성은 이미 있으나 사용은 3단계.
- **2단계 검증 제안**: 창 아래 화면이 1:1로 보이는지(알려진 패턴 픽셀 위치 비교), 이동·리사이즈 중에도 갱신되는지, 1단계 기능 회귀 없음, 종료 코드 0·java 프로세스 0개, CPU 사용량 과도하지 않음.
