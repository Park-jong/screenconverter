# 6-14 피드백: 6단계(조작 UI) 완료 정리 (메인 에이전트 직접 정리)

## 판정: 6단계 완료
- 6-1~6-3 효과 선택 목록, 6-4~6-6 ASCII 텍스트 복사, 6-7 옵션 패널·일시정지, 6-8 메뉴 갱신 수정, 6-9 항상 위 버튼, 6-10 이미지 저장 버튼, 6-12 상태 문구 폭 맞춤을 개발했고 6-11 통합 검증(A~H)과 6-13 재검증을 통과. 최종 빌드 테스트 194개, 최소 창 518x427.
- 6-11 의 제품 결함 1건(낮음: 한글 폴더 이름 상태 문구가 168px 초과)은 6-12 로 수정, 6-13 에서 PASS. 6-11 의 나머지 FAIL 3종은 하네스 쪽 원인(`G size` 기준 오류, `6 rapid saves`는 저장 중 재클릭 무시 설계, `paused option change`는 훅 없는 인스턴스의 균일 이미지).
- 근거: 메뉴 갱신 수정은 마우스 드래그 144회 클릭에서 상태·화면·이벤트 불일치 0(대조군 옵션 off 에서는 24/24·23/24 재현), 일시정지 중 워커 CPU 0·정지 프레임 저장 정확, 항상 위 토글이 실제 Z순서·`WS_EX_TOPMOST` 를 바꾸고 affinity 0x11·HWND 불변, 이미지 저장 PNG 가 표시 이미지와 픽셀 동일(EDT 한 번에 비교)·중복 접미사·실패 시 앱 무정지, 키 바인딩 충돌 없음, 닫기 5경로 모두 0.2~0.3초·종료 코드 0.

## 남은 낮은 항목(체감 문제가 보고될 때 재검토)
- 일시정지 중 옵션 변경은 하네스 인스턴스가 자기 자신을 캡처하는 환경에서는 확인 불가(Main 경로 PASS).
- Main 경로(affinity 적용 창)의 시각 비교와 항상 위·이미지 저장 반복 클릭 시 화면 불일치 횟수는 자동으로 못 찍어 **사용자 육안 확인**에 포함.
- 저장된 PNG 와 클릭 후 표시 이미지의 60픽셀 차이(6-13)는 클릭 직후 캡처 루프가 프레임을 갱신해서로 추정(6-11 에서는 EDT 한 번에 복사·저장으로 동일 확인).
- 최소 창이 518x427 로 커짐(메뉴 항목 증가): 낮은 화면 높이 PC 에서는 부담. 필요하면 버튼 2개를 한 줄에 놓아 줄일 수 있음.
- 5단계 이월(60fps 14/21ms 교대, 간헐적 max 44ms, 스핀 마진 1ms 축소)은 체감 문제가 있을 때만.
