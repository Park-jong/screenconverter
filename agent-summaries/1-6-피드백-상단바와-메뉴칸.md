# 1-6 피드백: 상단바와 메뉴칸 (feedback-synthesizer 보고, 메인 에이전트가 대신 저장)

## 판정: 이번 루프 완료 (추가 개발 루프 불필요)
- 요청 (1) OS 제목줄 유지: 충족. 스크린샷으로 제목줄(아이콘, "Converter", 최소화/최대화/닫기) 확인, Robot으로 제목줄 드래그·리사이즈 PASS.
- 요청 (2) 오른쪽 메뉴 칸: 충족. MenuPanel EAST 폭 180px, 어두운 배경, "메뉴(준비 중)".
- 회귀 없음: captureRect가 7개 상태에서 CapturePanel 내부와 1px 오차 없이 일치, 제목줄·테두리·메뉴 칸 미포함, 닫기 4가지 종료 코드 0.

## 사소 관찰 처리
- **(a) 최소 창 크기 400x250에서 캡처 영역이 약 202x209로 축소**: 지금 고치길 권장. `setMinimumSize`가 프레임 바깥 크기 기준이라 제목줄·OS 테두리·메뉴 칸 180px을 빼면 작아짐. 4단계 모자이크 입력이자 6단계 미리보기 기준이므로 불편. 의도된 동작으로 보기 어려움.
  - 구현: 상수 대신 계산 — `setVisible`/`pack` 이후 `getInsets()` + MenuPanel 폭 180 + content border를 더해 `setMinimumSize` 갱신. 목표 최소 캡처 영역 약 320x180 이상(조정 가능). 단순안은 MIN_W=520, MIN_H=330 상수. DPI/테마에 따라 insets가 달라지므로 계산이 안전. 초기 크기 640x360은 새 최소치보다 크게 유지. 장식 변경 금지(생성자에서만), `setMinimumSize`는 HWND를 재생성하지 않아 안전.
  - 재검증: 최소 크기에서 captureRect가 목표 이상인지, 기존 7개 상태 일치, 닫기 종료 코드 0, `mvn -B package` 통과. 건드리지 말 것: `captureOnce`, 훅 구조, `closeApp`, 둥근 모서리 처리.
- **(b) Windows 11 둥근 모서리로 captureRect 좌하단 5픽셀에 창 뒤 배경**: 6단계로 연기. 기능상 문제 없음. 대안은 CapturePanel border를 1px → 약 4px로 키워 inner가 더 안쪽을 잡게 하는 것. 3단계에서 자기 창을 제외하면 문제의 성격도 바뀜.

## 이후 단계 영향
- **3단계**: WDA_EXCLUDEFROMCAPTURE는 HWND 단위라 장식된 JFrame에 걸면 제목줄·OS 테두리·MenuPanel·CapturePanel이 모두 캡처에서 빠짐 — 창 전체가 한 HWND이므로 정상이자 기대 동작. 제외 영역은 검은색이 아니라 창 뒤 실제 화면이어야 함(Win10 2004+). 최대 위험은 Robot(GDI BitBlt)이 이 플래그를 따르는지 여부 → 첫 실측 항목. 캡처 루프가 도는 상태의 동적 비교는 아직 한 번도 안 했으므로 3단계가 첫 기회. DPI 125/150%·다중 모니터도 함께. HWND는 `onShown`/`shownHook`에서 획득, 장식 변경 금지 유지.
- **4단계**: 입력 영역 크기 = captureRect(위 (a) 수정의 이점). 렌더 결과는 `content.setImage`로 같은 패널에 그려 좌표 어긋남 방지.
- **5단계**: `getLocationOnScreen()`과 Robot 좌표의 DPI 스케일 차이를 125/150%에서 실측. 최소 크기 계산은 DPI 스케일된 insets에 의존. 33ms 주기·invokeLater 구조는 성능 기준선.
- **6단계**: MenuPanel은 캡처 영역 밖이라 조작 UI를 넣어도 모자이크 대상에 섞이지 않음. 폭 180이 충분한지 이 단계에서 결정(접기 방식 가능). 메뉴 폭이 바뀌면 최소 크기 계산이 따라가야 함. 텍스트 입력 컴포넌트가 들어가면 ESC 바인딩 충돌 점검. 둥근 모서리 5px는 border 키우거나 무시.

## 문서 정리
`1-1-*.md`, `1-3-*.md` 의 ResizeLogic·직접 리사이즈 서술은 폐기됨. 테스트는 CaptureRegionTest 3개뿐이며 captureRect 일치 검증은 스크립트에 의존하므로 검증 스크립트를 보존하면 3단계 이후 회귀에 재사용 가능.
