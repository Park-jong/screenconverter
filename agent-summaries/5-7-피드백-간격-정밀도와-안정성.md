# 5-7 피드백: 간격 정밀도와 안정성 (메인 에이전트 직접 정리 — 검증 시간 단축 요청에 따라 피드백 에이전트 호출 생략)

## 판정: 5-5 완료, **5단계(성능과 안정화) 목표 달성으로 종료**
- 동적 화면 목표(30fps 이상, 간격 균일, CPU·종료·오류 안정성)를 충족: 30fps 간격 p95 49 → 35.2ms(독립 폴링, 3회 일치), p99 35.6~35.8ms, 60fps는 p95 21ms·60.0fps. 종료 0.2~0.3초, 오류 로그 폭주 해소(카운터 메시지 3초 13줄), 오류·captureRect null에서도 100% 스핀 없음, import 검사 allowlist가 실제 위반(`java.awt.Button`, 완전수식 `Toolkit`)을 FAIL로 잡음. 106개 테스트 통과.
- 기본값은 30fps 유지(사용자가 `-Dconverter.fps=60` 등으로 조정 가능). 30fps CPU는 640x360에서 13%, 1280x720에서 29%(코어 1개 기준)로 스핀 마진 2ms 때문에 이전보다 약 +6%p.

## 낮음 관찰 처리
1. **스핀 마진 2ms → 1ms 축소**: 시뮬레이션에서 p95는 0.2ms 이내로 유지되지만 CPU 이득이 0.3~1%p에 불과하고 실제 앱 효과는 미측정이라 **변경하지 않음**(필요해지면 마진 상수 한 줄 변경 + 재측정으로 7단계 이후 검토).
2. **60fps 14/21ms 교대 패턴**: 평균·p95가 목표 범위 안이라 지금은 수정하지 않음. 동영상·게임에서 체감 끊김이 보고되면 sleep 분해 방식(10 배수 보정과의 상호작용) 재검토.
3. **간헐적 max 약 44ms**: GC 시각과 상관만 확인(일시정지는 1ms), 직접 원인 미확정. 사용자 체감 문제가 생기면 grab/EDT 분리 계측으로 조사하고, 그때 `BufferedImage` 재사용을 재평가(근거 없는 최적화는 하지 않음).
4. 오류 중 fps=max의 워커 CPU 약 20%: 100% 스핀이 아니므로 조치 없음.

## 보류 유지
`BufferedImage`/배열 재사용, `DataBufferInt` 직접 접근 공통화·블록 평균 중복 정리(성능 이득 없음, 회귀 위험) — 근거가 생길 때까지 보류. DPI·다중 모니터는 구현하지 않음(사용자 환경 결정).

## 사용자 확인이 필요한 것
실제 동영상·게임 위에서 체감 부드러움(5-3·5-6은 움직이는 패턴 창으로 대체 측정). 직접 숫자를 보려면 `java -Dconverter.metrics=true -jar target\converter.jar`(5초마다 fps·간격·단계별 시간 출력), 목표 fps 변경은 `-Dconverter.fps=60`(또는 `max`).
