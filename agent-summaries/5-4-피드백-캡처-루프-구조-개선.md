# 5-4 피드백: 캡처 루프 구조 개선 (메인 에이전트 직접 정리 — 사용자가 검증 시간 단축을 요청해 피드백 에이전트 호출을 생략)

## 판정
5-2(캡처 루프 구조 개선)와 5-1(계측 도구)은 **완료**. 5-3 검증이 계측 수치를 독립 측정(±1%)으로 확인했고, 30fps 목표(21/17fps → 30.0fps)와 안정성(종료·예외·마지막 프레임·제외 실패 경고) 요구가 충족됨. 효과 계산은 병목이 아니며 fps는 목표 fps 설정과 캡처 시간(작은 창 약 7ms, 큰 창 약 12ms)이 좌우함.

## 5-3 발견 3건의 처리 — 다음 루프(5-5 개발)에서 함께 수정
1. **간격 p95 약 48.5ms(parkNanos 15.6ms 올림)** — 동영상·게임의 부드러움에 직접 관련, 수정. 대기를 `Thread.sleep(남은 ms − 2ms)`(결과가 10의 배수이면 1을 빼 15.6ms 올림 구간을 피함) + 마지막 약 2ms `Thread.onSpinWait` 스핀으로 교체(5-3이 3·7·12·19·26ms 요청에서 오차 0.03ms 이내로 확인). CPU 추가분은 프레임당 약 2ms(30fps에서 약 6%p 이하로 추정, 측정해서 확인). 이 계산은 `FramePacer`에 순수 로직으로 두고 단위 테스트.
2. **ErrorThrottle 마지막 키만 기억** — 키별 마지막 출력 시각 맵(크기 상한, 오래된 키 제거) + 전체 출력 상한(예: 5초에 최대 N줄)으로 폭주 방지. 단위 테스트.
3. **fps=max에서 예외가 계속 나거나 captureRect가 null이면 CPU 100% 스핀** — 오류 직후와 captureRect null일 때 최소 대기(예: 5~10ms) 백오프.

## 보류·미룸
- **할당 재사용(프레임당 약 7MB)**: 보류. 측정된 GC 일시정지 합계가 15초에 5~108ms(1280x720, 60fps에서 최대 108ms)로 0.7% 이하이고 프레임 간격 max에 GC 상관 증거가 없음. 타이밍 수정 후 재측정에서 간격 max/p99가 GC와 상관을 보일 때만 진행(측정이 먼저).
- **DataBufferInt 직접 접근 공통화·블록 평균 중복 정리**: 성능 이득이 없는 유지보수 리팩터링이고 5개 효과에 걸치는 회귀 위험이 있어 지금은 하지 않음(사용자 목표는 동적 화면의 부드러움). 필요해지면 7단계 정리 때 검토.
- **EffectPackageImportsTest allowlist 전환**: 작은 안전망(30~50줄)이라 5-5에 함께 포함(4-12 피드백 권고).
- 60fps 이상 기본값 변경은 하지 않음(30fps 기본 유지, 사용자가 `-Dconverter.fps`로 조정). 사용자가 실제 동영상·게임에서 체감 후 요청하면 재검토.
- DPI·다중 모니터는 구현하지 않음(사용자 환경 결정).

## 5-5 후 검증(5-6) 범위
빌드·테스트, 간격 p95/p99 전후 비교(독립 폴링: 30fps에서 p95가 33ms에 가깝게 내려오는지), 30fps CPU 증가분, 예외 폭주 로그·백오프 동작, 종료·제목·메뉴 회귀 스냅샷. 장시간·전수 비교는 생략.
