# 4-1 개발: 모자이크 효과 (code-writer 보고, 메인 에이전트가 대신 저장)

`mvn -B package` BUILD SUCCESS, 테스트 18개 통과(신규 9개). 창은 띄우지 않았고 육안·통합·동적 검증은 하지 않음. java 프로세스 잔존 없음. 리뷰 판정 없음.

## 신규 (`effect/`)
- `Effect.java`: `BufferedImage apply(BufferedImage src)`. 입력 불변, 같은 크기 TYPE_INT_RGB 새 이미지 반환. Swing/JNA/AWT 컴포넌트 import 없음.
- `IdentityEffect.java`: 입력의 정확한 복사본 반환(3단계 동작으로 복귀용).
- `MosaicEffect.java`: 블록별 평균색.
  - `MosaicEffect(int)`, 인자 없는 생성자는 기본 블록 10(`DEFAULT_BLOCK_SIZE`), `blockSize()` getter. blockSize < 2(`MIN_BLOCK_SIZE`)는 `IllegalArgumentException`(클램프 안 함, Javadoc에 명시).
  - 블록 격자 원점은 이미지 (0,0). 창이 움직이면 모자이크가 출렁이는 것은 정상(Javadoc에 결정 기록).
  - 마지막 열/행 부분 블록은 실제 픽셀 수로 나눔. 반올림은 채널별 정수 합에 `(sum + count/2) / count`(half-up), 알파 무시(코드 주석 명시). 블록이 이미지보다 크면 블록 1개 = 전체 평균 1색.
  - 입력은 `getRGB` 일괄 복사로 읽어 어떤 이미지 타입이든 받고 원본 불변, 출력은 `DataBufferInt`에 직접 씀.

## 수정
- `ui/OverlayWindow.java`: `private volatile Effect effect`(기본 `IdentityEffect`) + `setEffect(Effect)`(null 거부). `captureOnce`(워커)에서 `effect.apply(img)` 후 완성 이미지만 `invokeLater`로 `CapturePanel.setImage`. 효과 예외는 기존 `catch (RuntimeException)`으로 루프 유지.
- `Main.java`: 훅 설정 앞에 `window.setEffect(new MosaicEffect(10))` 한 줄. setShownHook·setVisible·onShown 순서, win32/*, MinimumWindowSize, 창 장식, closeApp 불변.
- 결과 이미지 크기 = captureRect 크기. CapturePanel은 미수정(기존대로 insets 안쪽에 그림).

## 테스트 (`MosaicEffectTest`, 9개)
4x4·블록 2 손계산, 2x2·블록 2, 블록이 이미지보다 큼(3x2·블록 50, 전체 평균 1색), 10x7·블록 4 전수 비교와 부분 블록 손계산값 59, 단색, 입력 불변·크기·타입 유지, 비 RGB 입력 타입, IdentityEffect, blockSize 1·0·-5 거부.
