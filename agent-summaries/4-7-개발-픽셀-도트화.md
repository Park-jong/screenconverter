# 4-7 개발: 픽셀 도트화 (code-writer 보고, 메인 에이전트가 대신 저장)

`mvn -B package` BUILD SUCCESS, 테스트 46개 통과(기존 27 + Palette 8 + PixelDotEffect 11, EffectRegistryTest 갱신). 창은 띄우지 않았고 성능 측정 뒤 java 프로세스 잔존 없음. 육안·통합 검증 없음. 리뷰 판정 없음.

## 신규 (`effect/`)
- `Palette.java`: 불변. `NONE` 상수, `Palette.fixed(int[])` 팩토리, `GAMEBOY_4`·`EGA_16`(요청한 순서·값 그대로). null/빈 배열은 IAE, 입력과 `colors()` 반환값 모두 방어적 복사. `nearest(rgb)`: 정수 제곱거리, 동점이면 앞선 색. `NONE.nearest`는 `IllegalStateException`. 요청에 없던 추가 메서드 `contains`, `size`, `kind`, `isNone`.
- `PixelDotEffect.java`: 한 패스(블록 평균 → 양자화 → 격자), 생성자 검증(blockSize<2 IAE, 격자+blockSize<4 IAE, palette null IAE). 기본 블록 상수 8, 격자 색 `GRID_COLOR=0x202020`. 입력이 TYPE_INT_RGB/ARGB이고 배열이 촘촘한 레이아웃이면 `DataBufferInt` 배열을 복사 없이 읽음, 그 외 타입은 `getRGB`로 한 번 변환. 출력은 새 TYPE_INT_RGB.

## 수정
- `EffectRegistry.java`: 5=도트 16색, 6=도트 게임보이, 7=도트 격자, 8=도트 16색+격자(모두 블록 8). 9번 비워 둠.
- `GrayscaleEffect.java`: 주석만 — 소수 값 주석(149.685 등)이 +500 이전 값이라는 설명, double 식이 .5 경계 3,464조합에서 1 낮게 나와 정수식이 기준(4-5 전수 검증).
- `OverlayWindow`, `Main`, `win32/*`, `MosaicEffect` 미수정.

## 테스트
- `PaletteTest`: 상수 값, 게임보이/EGA의 순흑·순백·중간 회색·순빨강 손계산, 동점 케이스(순서를 바꿔 앞선 색 선택 확인), null/빈 배열 거부, 방어적 복사.
- `PixelDotEffectTest`: 팔레트 NONE + 격자 off == `MosaicEffect`(여러 크기·블록 2~200), 4x4 손계산 3종(EGA 블록 2, EGA 블록 4+격자, 게임보이 블록 2), 격자 켬/끔이 격자 위치 외 동일, 10x7·블록 4 부분 블록의 격자 위치·평균, 격자 위치를 뺀 모든 픽셀이 팔레트 안·블록 내부 단색, 입력 불변·크기·타입, 3BYTE_BGR 입력, 생성자 IAE(blockSize 1과 0, 격자+블록 3, palette null).
- `EffectRegistryTest`: 항목 8개, 이름·순서·블록 8·팔레트·격자 여부 검증, 미등록 번호 0/9/10/-1, `register` 테스트의 새 번호 9.
- 개발자가 손계산 중 오류 하나를 테스트로 잡아 고침: 4x4 블록 4 평균 (128,141,40)의 최근접 EGA 색은 AA5500(거리 6500, 555555는 7010). 구현 문제는 아니었음.

## 성능 (1738x1007 랜덤 이미지, 워밍업 100회 후 300프레임, `apply`만)
`PixelDotEffect(8, EGA_16, true)` 중앙값 3.67ms / p95 4.73ms, `(8, GAMEBOY_4, false)` 3.24 / 4.22ms, `MosaicEffect(10)` 6.10 / 7.11ms. 도트화가 더 빠른 이유는 입력 `getRGB` 복사를 건너뛰기 때문.
