# 6-6 피드백: ASCII 텍스트 복사 (메인 에이전트 직접 정리 — 검증 시간 단축 요청에 따라 피드백 에이전트 호출 생략)

## 판정: 루프 A 완료
요청("아스키아트 모드는 복사가 가능했으면 좋겠어") 충족: ASCII(9번) 모드에서 메뉴 버튼 "텍스트 복사"와 Ctrl+C가 화면 격자와 같은 문자열을 시스템 클립보드에 넣음(전 칸 2552개 일치, 줄·열 수 일치, 마지막 줄 개행 없음, ASCII만). 다른 효과에서는 비활성·안내, 클립보드 점유 시 "복사 실패" 안내와 EDT 무정지, 움직이는 화면 20회 연속 복사 정상, 최대화 14k자 약 9ms. 기존 ASCII 이미지는 144건에서 비트 단위로 불변, 최소 창 518x265(캡처 320x224·메뉴 9행·버튼·상태 문구 모두 보임), 닫기 4가지·affinity·fps(p95 36ms) 회귀 없음. 테스트 124개.

## 처리할 항목
1. **오래된 텍스트·1프레임 앞섬(Low, 코드 리뷰로만 확인)**: `lastGrid`가 publish 이전에 갱신되고, 다른 효과에서 9번으로 돌아온 직후 첫 새 프레임 전에 복사하면 이전 텍스트(크기가 다를 수 있음)가 복사될 수 있음 → **루프 B(6-7)에서 수정**: 효과가 바뀌거나 ASCII 설정이 바뀌면 격자를 초기화하고, 복사 텍스트는 화면에 게시된 프레임의 텍스트와 짝이 되게(프레임과 함께 게시) 한다. 일시정지 기능이 들어오면 정지 프레임의 텍스트를 복사하게 되므로 같은 구조가 필요함.
2. **줄 끝 공백 보존 실물 미확인, 메모장 붙여넣기 미확인**: 줄 끝 공백 제거 옵션을 루프 B에서 만들 때 단위 테스트로 보강, 사용자가 실제 붙여넣기로 확인.
3. **CPU 약 46%(거의 전체화면 1920x1040·9번)**: 큰 영역 grab(평균 약 19ms)이 대부분. 사용자 영역이 작을수록 낮고 `-Dconverter.fps` 로 조절 가능하므로 조치 없음.
4. 비활성 버튼 클릭 문구·툴팁·2.5초 자동 지움의 화면 확인은 사용자 육안으로 갈음.

## 루프 B(6-7~6-9) 범위 확정
효과 옵션 패널(블록 크기·임계값·ASCII 칸 크기·줄 끝 공백 제거), 일시정지, 위 1번 수정. 효과 번호 체계(1~9)와 5~8 변형은 유지(옵션은 현재 선택된 효과의 매개변수만 조절).
