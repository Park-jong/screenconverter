# 5-6 검증: 간격 정밀도와 안정성 (code-verifier 보고, 메인 에이전트가 대신 저장)

판정: 필수 항목 1~6 모두 확인, 5-5 변경이 요구사항을 만족. 심각한 문제·회귀 없음, 낮은 심각도 관찰 3건. 제품 소스 수정 없음, 하네스는 `v5\v56` 아래(M2, Sim, E2, 주입 복사본 p1·p2). 환경: 배율 100%, 단일 모니터.

## 1. 빌드·불변성
`mvn -B clean package` BUILD SUCCESS, 테스트 106개 통과. effect/* 알고리즘 파일(15:21~16:12), win32/*(15:13), MenuPanel(16:49), CapturePanel(14:45), MinimumWindowSize(15:08)는 5-5 시점(17:35~17:37) 이전 값 그대로. 5-5에서 바뀐 것은 FramePacer, OverlayWindow, ErrorThrottle, `effect/package-info.java`와 테스트뿐.

## 2. 코드 리뷰
- `FramePacer.plan`: 남은 시간 ≤ 0이면 `{0,0}`, (남은 − 2ms)가 1ms 미만이면 스핀만, 정수 ms가 10의 배수이면 1 감소해 그만큼 스핀으로 넘김, sleep+스핀 = 입력. `awaitUntil`: sleep 중 interrupt는 `InterruptedException`, 스핀 중에는 `Thread.interrupted()`로 같은 예외, 스핀 조건 `deadline - nanoTime() > 0`이라 deadline을 넘겨 스핀하지 않음, sleep이 deadline을 넘겨 깨어나면 바로 반환(오버슈트 보정 없음, 정상).
- `captureLoop`: `InterruptedException`이면 플래그 복원 후 break, `withBackoff`는 `failed`일 때만 대기를 10ms 이상으로(정상 프레임 영향 없음, 실측 확인), `captureRect==null`·grab null·예외 시 `failed=true`.
- `ErrorThrottle`: 키별 맵(LinkedHashMap, 64키 상한, 오래된 키 제거) + 5초 창 10줄 전체 상한, 시계는 `now` 인자로 주입, 억제 건수는 `takeSuppressed`(전체)·`takeSuppressedFor`(키별). 경미: 키가 제거되면 그 키의 억제 건수도 사라짐.
- `EffectPackageImportsTest.findViolations`: 주석·문자열·문자 리터럴·텍스트 블록 제거, `;` 분리, `import static` 멤버 제거, `package` 문 건너뜀, 완전수식 정규식 검출. 검출기 단위 테스트 5개.

## 3. 간격 개선 독립 측정
CapturePanel.image 참조 변경 스핀 폴링, 640x360·효과 2·fps=30·15초·3회 실행(5-3 값은 33.3/48.5/49.7). avg 33.3ms·fps 30.0(3회 모두), p50 34.7ms, **p95 35.2ms(3회 모두)**, p99 35.6/35.6/35.8ms, max 44.7/36.7/44.1ms. 36ms 넘는 간격은 실행당 최대 2개. 프로세스 CPU 합계 약 109~110%(폴러가 코어 1개이므로 워커·EDT는 약 10%). p95는 보고(약 36ms)보다 낮은 35.2ms로 재현, max 44ms 안팎은 3회 중 2회 재현(나머지 1회 36.7ms). **max 원인은 확정하지 못함**: 큰 간격은 2회에서 정확히 1번씩, 둘 다 JVM 업타임 18.06~18.08초 — `-Xlog:gc`의 마지막 Young GC(18.049s·18.069s, 일시정지 약 1ms) 시작 직후 8~10ms 지점이며 같은 윈도의 다른 GC(5.8s, 8.2s 등)에서는 큰 간격 없음 → GC 일시정지 자체(1ms)보다 GC 시점에 겹친 다른 지연(EDT 표시나 grab 지연)일 가능성(grab과 EDT 분리 계측은 안 함).

## 4. 스핀 마진 시뮬레이션 (별도 하네스 `Sim`: FramePacer.plan과 같은 알고리즘, 7ms 바쁜 작업 + 33.3ms 주기, 20초)
7ms 작업만의 CPU 기준선 21.0%.
| 마진 | p95 | p99 | max | CPU |
|---|---|---|---|---|
| 0.5ms (2회) | 33.6 / 33.4ms | 34.6 / 34.0ms | 38.6 / 34.7ms | 23.3 / 22.7% |
| 1ms (2회) | 33.5 / 33.5ms | 34.1 / 33.9ms | 34.9 / 34.4ms | 23.3 / 22.9% |
| 2ms (2회) | 33.3 / 33.3ms | 33.5 / 33.6ms | 34.6 / 35.2ms | 23.6 / 26.8%(2회째는 소음으로 보임) |
순수 시뮬레이션에서는 마진 1ms로 줄여도 p95가 0.2ms 이내로 유지, CPU 차이는 마진 0.5/1ms와 2ms 사이 약 0.3~1%p. 시뮬레이션의 sleep 해상도는 약 1ms이며 실제 앱의 p95 35.2ms는 grab·EDT 변동 때문이라 직접 비교 불가. **실제 앱에서 1ms 마진의 효과는 측정하지 않음**(제품 코드 수정 금지).

## 5. 안정성
- (a) 닫기(ESC·X·우클릭, fps=30과 fps=max 각각, 계측 끔): ESC 202~229ms, X 307~310ms, 우클릭 약 800~850ms(스크립트의 400ms 대기 포함), 6개 조합 모두 종료 코드 0·stdout/stderr 0바이트.
- (b) 오류 주입(RuntimeException 같은 메시지, AssertionError, 번갈아 나오는 키, 카운터 메시지 각 3초, 전체 약 13.5초): stderr 96줄(스택트레이스 포함, fps=30과 max 동일), 카운터 메시지 3초 구간은 13줄 → 5초 창 10건 상한 작동. 오류 중 프레임 갱신 0, IdentityEffect로 복귀 시 즉시 복구(fps=30 30/s, max 143/s). 워커 CPU(스레드 CPU 시간): 정상 8.6%(fps=30)·11.7%(max), 오류 중 7~11%·약 20~22% — 100% 스핀 없음(10ms 백오프 작동). 오류 중 max의 워커 CPU가 정상보다 높은 이유는 백오프의 마지막 2ms 이상이 스핀이고(20%) grab(약 100회/s)도 계속 실행되기 때문으로 추정(직접 확인 안 함).
- (c) `captureRect`를 리플렉션으로 null: fps=30 워커 CPU 3.1%·프레임 갱신 0, fps=max 20.8%·갱신 0, 복원하면 복구(29/s, 144/s), 100% 점유 없음.
- (d) `EffectPackageImportsTest` 복사본 시험: `import java.awt.Button;` 한 줄 주입 시 FAIL(`names outside the allowlist: [IdentityEffect.java: java.awt.Button]`), `java.awt.Toolkit.getDefaultToolkit();` 호출 주입 시 FAIL(`[IdentityEffect.java: java.awt.Toolkit.getDefaultToolkit]`), 제품 소스는 통과(106개).

## 6. 회귀 스냅샷
최소 창 518x221·캡처 320x180, 제목줄 드래그 (100,60)→(200,110)로 이동하고 captureRect가 따라감, 메뉴 클릭(7번 행)·숫자 키 1~9·`selectEffect`·목록 `setSelectedIndex`에서 제목과 메뉴 선택 일치, 효과 성질(원본 화면과 평균 차 0.00, 흑백 모두 회색 244색, ASCII 12색), `GetWindowDisplayAffinity` 0x11, alwaysOnTop true, 30fps CPU(640x360·효과 2·정적) 13.1%(보고 13%와 같음). 60fps(15초, 폴러 CPU 제외 약 15~25% 코어 추정): 640x360 효과 2 avg 16.7 / p50 14.3 / p95 21.0 / p99 21.3 / max 21.6, 60.0fps. 1280x720 효과 9 avg 16.7 / p95 21.1 / p99 21.3 / max 22.3, 60.0fps. 보고값 p95 16.7/21.5와 일치(1280x720 효과 9는 p95만 비교). 60fps CPU 24%/52%는 폴러(코어 1개)가 섞인 합계(115%, 125%)에서 폴러를 빼면 15%/25%로 추정되나 보고값 정의와 달라 직접 비교하지 못함.

## 발견 사항 (심각도 낮음)
1. 60fps 간격이 14ms와 21ms로 번갈아 나옴(p50 14.3ms, p95 21.0ms, 평균 16.7ms) — 목표 16.7ms 안쪽이지만 균일하지 않음. 30fps에서도 p50 34.7ms·평균 33.3ms로 비슷한 패턴. 원인은 sleep 해상도나 10 배수 보정과의 상호작용으로 추정(확인 안 함).
2. max 약 44ms 간격이 간헐적으로(3회 중 2회) 남음, 원인 미확정(GC 시각 상관만 확인).
3. 오류 상태에서 fps=max일 때 워커 CPU가 약 20%로 정상 상태보다 높음(100% 스핀은 아님).
