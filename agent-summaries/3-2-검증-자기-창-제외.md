# 3-2 검증: 자기 창 제외 (code-verifier 보고, 메인 에이전트가 대신 저장)

판정: 차단 문제 없음, 완료 기준(반복 없이 아래쪽 화면이 정상으로 보인다) 충족. 환경: Windows 11 26200, 1920x1080, 배율 100%, 단일 모니터, JDK 17. 소스 수정 없음.

## 빌드·코드 리뷰
- `mvn -B clean package` BUILD SUCCESS, 테스트 9개(CaptureRegion 3, MinimumWindowSize 3, AffinityFlags 3) 통과.
- WindowsDisplayAffinity: null/비 Windows → false, getComponentPointer null → stderr 한 줄 + false, Set 후 Get 되읽어 isExcluded 판정, 실패 시에만 GetLastError 출력, UnsatisfiedLinkError|RuntimeException catch. 정상 경로 출력 없음(jar 실행 stderr 0바이트).
- JNA 격리: `com.sun.jna` import는 win32 패키지 안에서만(밖 grep 0건). `DisplayAffinity`는 Component·boolean만 노출.
- Main 훅 연결, onShown 순서(applyMinimumSize → 훅 → updateCaptureRect → startCapture), 창 장식·MinimumWindowSize·MIN_CAPTURE·closeApp·captureOnce 구조 불변.
- 낮음/정보: `isCaptureExcluded`는 호출처 없는 getter(영향 없음). 제외 실패 시 앱은 재귀 상태로 계속 실행되며 폴백(숨김·경고)은 없음.

## 실측
- (a) 별도 프로세스 패턴 창(B.java, 전체화면, R=(7x)&255, G=(5y)&255, B=(3(x+y))&255) + Main 경로 하네스(D.java)가 CapturePanel의 image 필드를 리플렉션으로 읽어 이미지 (0,0) 픽셀에서 오프셋을 역산해 전수 비교. 최종 이미지 442x319의 역산 오프셋 (53,232) = captureRect 기준 예상값. 실제 `java -jar` 프로세스는 J.java로 Robot이 오버레이 영역을 찍어 뒤쪽 패턴과 비교: 창 안쪽 120000픽셀 불일치 0 (단, Robot 화면 결과이며 DWM 합성 화면을 사람 눈 기준으로 비교한 것은 아님).
- (b) 캡처 루프 가동 중 동적 비교(5ms 주기 읽기): setBounds 연속 변경, setLocation 이동, 100x100 리사이즈(최소 클램프), 최대화·복원, Robot 제목줄 드래그, Robot 가장자리 리사이즈를 3라운드 반복 → 760프레임 good=760, bad=0. 무한 반복 징후 없음.
- (c) 음성 대조(affinity 미적용): 760프레임 good=2(첫 그리기 전 초기 프레임), bad=758. 정지 시 역산 오프셋 (94,179) ≠ 예상 (53,232). 재귀를 정확히 검출.
- (d) 외부 확인: 별도 프로세스에서 jar 실행 후 FindWindowW("Converter") + GetWindowThreadProcessId로 소유 확인, GetWindowDisplayAffinity = 0x11 (5회 모두).
- (e) 1-8 회귀 통과: 제목줄 드래그 +100,+100 정확, 최소 크기 외부 GetWindowRect 518x221·내부 320x180(최대화 1738x1007), captureRect 내부와 일치. 닫기 ESC(클릭 후) 0, ESC(클릭 없이) 첫 실행 미종료·재시도 2회 0, X 버튼 0, 우클릭 '닫기' 0 — 모두 stderr·stdout 0바이트. ESC(클릭 없이) 첫 실행 미종료는 포커스 이탈로 추정(1-3 이월 항목, 직접 계측으로 확정하지는 않음). alwaysOnTop = WS_EX_TOPMOST.
- (f) CPU: `java -jar` 5초 156ms (코어 1개 기준 약 3.1%, 20코어).
- java 프로세스 0개.
