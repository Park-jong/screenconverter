# 6-3 피드백: 메뉴 효과 선택 목록 (feedback-synthesizer 보고, 메인 에이전트가 대신 저장)

근거: 6-1·6-2 보고서만(소스는 읽지 않음).

## 판정: 완료(통과)
빌드·테스트 73개, 필수 5개 항목 모두 통과, 새 결함 없음. 클릭·숫자 키·다른 스레드 호출 동기화 맞음(무작위 20회 불일치 0), captureRect 불변·메뉴와 겹침 없음, affinity 0x11 유지, 종료 경로 4종 회귀 통과. "선택된 것이 무엇인지 보이게" 요청은 충족: 파란 배경 + 흰 굵은 글씨 행 강조, 상단 "현재: …" 헤더, 창 제목 갱신, 클릭/숫자 키/코드 호출이 같은 경로로 동기화. 덤으로 메뉴 클릭으로 창이 활성화되어 "캡처 영역을 한 번 클릭해야 키가 먹는" 제약이 완화됨.

## 남는 공백(사용자가 직접 볼 점)
- 실제 오버레이 창에서 선택 행의 파란 띠가 눈에 잘 띄는지(두 에이전트 모두 오버레이를 Robot으로 못 찍어 MenuPanel을 BufferedImage로 paint한 이미지로 확인). 개발자가 본 "최소 크기에서 띠가 안 보임"은 검증자가 뷰어 문제로 판단했으나 원인은 재현하지 못함 → 사용자가 최소 크기·일반 크기에서 보면 해소.
- 스크롤바는 공백 아님(6-2가 14개 항목으로 렌더링 확인). 7번 도트 격자의 격자 성질 세부 검증은 안 했으나 효과 코드가 이번에 바뀌지 않아 위험 낮음. DPI·다중 모니터는 구현하지 않기로 한 한계(문서에 명시).

## 낮음/정보
- **(a) 최소 창 여유 2px, `MinimumWindowSize`가 메뉴 높이를 반영하지 않음**: 지금은 할 일 아님(효과 9개로 맞고, 넘쳐도 스크롤바 동작). 효과가 10개 이상이 되거나 글꼴이 바뀔 때, 또는 5단계 정리 여유가 있을 때 `MinimumWindowSize`를 메뉴 높이에서 계산(30분 이내 작업) — ROADMAP 이월에 기록.
- **(b) 이름 길이·한글 글꼴 폴백**: 폭 180에서 "9  ASCII 아트"와 한글 정상, Malgun Gothic 없으면 Dialog 폴백. 이름이 더 길어질 때의 잘림은 미검증(정보).
- **(c) 초기 1번 → `selectEffect(2)` 전환의 깜빡임**: Main이 창 표시 전에 호출하는 순서라면 사용자는 1번 상태를 보지 못함(검증이 시작 직후 제목·헤더·2번 행 강조 일치 확인). 표시 전인지는 코드로 직접 확인하지 않음 → 5단계에서 Main을 만질 때 순서 확인, 이상 있으면 생성자에서 초기 선택을 받게.

## 5단계(성능과 안정화) 권장 첫 작업 3개 — 순서: 측정 → 캡처 루프 구조 → 할당 제거
1. **측정 도구와 기준선**: 프레임 간격(평균·p95·최대), 실제 fps, CPU%, 단계별 시간(캡처·효과·paint)을 로그/임시 계측으로 남기되 기본 꺼짐. 동적 콘텐츠 측정: 1순위 동영상 재생(창 모드)을 캡처 영역 아래에 두고 60초 측정, 효과 1(원본)·2·5·9 각각. 대체: 매 프레임 색이 바뀌는 도형·이동 막대를 그리는 간단한 Swing 하네스(재현성 높음), 캡처 결과 이미지가 프레임마다 바뀌는지로 실제 갱신율 검증. CPU는 `Get-Process` 샘플링 또는 작업 관리자. 목표 20~30fps 이상, 지연·CPU 함께 기록. 시간은 5~10분(효과 4개 × 60초 정도).
2. **캡처 루프 구조 개선**: 현재 `scheduleWithFixedDelay` 33ms는 작업(캡처 약 14ms + 효과 + paint) 뒤에 33ms를 더 기다려 실제 약 20fps 안팎이거나 그 이하일 수 있음 → `scheduleAtFixedRate` 또는 작업 시간을 뺀 대기 방식, 밀리는 프레임은 건너뛰어 지연이 쌓이지 않게. 캡처와 효과/paint 분리(파이프라인)는 1번 측정 결과를 보고 결정(캡처 약 14ms는 Robot의 한계이므로 대기 구조부터). 같은 곳에서 Error 포획(루프가 조용히 죽는 문제)·제외 실패 경고도 처리.
3. **프레임당 약 7MB 새 할당 제거**: `BufferedImage`·배열 재사용(크기 변경 시에만 재생성), GC 정지로 인한 끊김 감소. 같은 파일을 만지는 김에 `DataBufferInt` 직접 접근 중복·블록 평균 중복을 공용 헬퍼로 정리.

## 나중으로 미룸
