# 창 폭 확대 후 메뉴 상태 오류 조사

## 결론
- 내부 상태는 정상, **화면(그려진 메뉴)만 한 클릭씩 뒤처지거나 갱신 안 됨**. 원인은 제품 로직이 아니라 마우스 드래그로 폭을 넓힌 뒤 Swing/Windows 부분 repaint 가 화면에 반영되지 않는 문제(확도: 현상 확정, 정확한 JDK 내부 원인은 추정).
- 조건: (1) 창 폭을 **마우스 드래그**로 넓힘 (setSize 로는 재현 안 됨), (2) 중앙 CapturePanel 이 30fps 로 계속 repaint 됨 (캡처 스레드 없으면 재현 안 됨), (3) 메뉴 칸이 창의 원래(생성/마지막 setSize 시점) 폭 바깥으로 완전히 밀려남. 640 시작 시 740 OK, 820 부터 STALE. 900 시작 시 850 OK, 1250 STALE.
- 상태 검증(선택 번호, 헤더, 제목, 일시정지, 복사 버튼 enabled, 옵션 컨트롤 값, effect 객체 필드)은 모든 폭에서 불일치 0. 마우스 이벤트(P/R/C)도 클릭당 1/1/1 정상 도착. EDT 왕복 평균 0.1~0.2ms, 최대 약 1ms. MenuPanel bounds 정상(폭 180 고정, 음수/겹침 없음), 창 최대 폭 약 1940.
- 화면 불일치 증거: 클릭 후 Robot 스크린샷의 선택 행 파란 픽셀 수가 메뉴 paint() 결과와 다름. 스크린샷에서 제목은 "흑백 2색"인데 메뉴는 "현재: 모자이크"로 남아 있음. 화면 값은 직전 상태와 같음(한 단계 뒤처짐). window.repaint() 하면 일시 복구.
- 같은 증상이 앱 코드 없는 최소 JFrame(BorderLayout, CENTER 30fps repaint + EAST JList)에서도 재현됨(애니메이션 정적 중앙이면 정상). affinity(0x11) 적용 상태에서도 동일 재현.
- 우회/수정 방향: `-Dswing.bufferPerWindow=true` 로 모든 폭에서 OK 확인(640→1540). 제품 쪽 수정안은 위 옵션 적용 또는 폭 변경(리사이즈 종료) 시 전체 repaint 강제. 코드는 수정하지 않음.
- H1/H3/H4/H5 기각(상태 정상, EDT 한가함), H6 일부(-Dsun.java2d.d3d=false, noddraw, volatileImageBufferEnabled=false 로는 안 고쳐짐).
- 미확인: 사용자 PC 와 정확히 같은 임계 폭, JDK 내부 원인, 최대화 버튼 경로.
