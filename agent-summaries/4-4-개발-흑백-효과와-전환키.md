# 4-4 개발: 흑백 효과와 전환키 (code-writer 보고, 메인 에이전트가 대신 저장)

`mvn -B package` BUILD SUCCESS, 테스트 27개 통과(신규 9: GrayscaleEffect 6 + EffectRegistry 3). 창은 띄우지 않았고 키 입력·제목 갱신은 실행으로 확인하지 못함. 육안·통합 검증 없음. java 프로세스 잔존 없음. 리뷰 판정 없음.

## 신규
- `effect/GrayscaleEffect.java`: `gray=(299R+587G+114B+500)/1000`(half-up, 알파 무시, 주석 명시). 기본 생성자 = 연속 흑백, `GrayscaleEffect(int threshold)` = `gray>=threshold`이면 255 아니면 0. 범위 밖 threshold는 `IllegalArgumentException`. 입력 `getRGB`로 읽어 불변, 같은 크기 새 TYPE_INT_RGB 반환. Swing/JNA/AWT 컴포넌트 import 없음. `isThreshold()` getter 추가.
- `effect/EffectRegistry.java`: 순수 로직, `record Entry(name, effect)`를 순서대로 보관. `register(name, effect)`는 다음 번호로 추가, `get(번호)`는 1부터 시작하는 번호로 `Optional<Entry>`(미등록은 empty), `size()`, `entries()`. `defaults()`: 1=원본, 2=모자이크(10), 3=흑백, 4=흑백 2색(128). 도트화·ASCII는 `defaults()`에 한 줄씩 추가하면 됨.
- `test/.../GrayscaleEffectTest.java`: 순수 색 5종 손계산 값(76, 150, 29, 255, 0) 하드코딩, 반올림 경계값, 이미 회색인 픽셀 불변, threshold 경계(128/127/129, 0, 255, 빨강 gray=76), 입력 불변·크기·타입 유지(ARGB 입력), 잘못된 threshold(-1, 256) 거부.
- `test/.../EffectRegistryTest.java`: 기본 등록 4개의 이름·순서·종류, 미등록 번호(0, 5, 9, -1), `register` 추가 항목 번호.

## 수정
- `ui/OverlayWindow.java`: `EffectRegistry.defaults()` 필드, `public boolean selectEffect(int number)`(등록된 번호면 `setEffect` + `setTitle("Converter - " + 이름)` 후 true, 미등록은 무시하고 false), `installEffectKeys()`(숫자 키 1~9와 숫자패드 1~9를 ESC와 같은 방식, `content`의 `WHEN_IN_FOCUSED_WINDOW` InputMap/ActionMap으로 `selectEffect`에 연결, 액션은 EDT 실행). 6단계 UI 전까지의 임시 수단임을 주석에 명시. 장식 설정·훅 순서·captureOnce·closeApp·MinimumWindowSize·win32/* 불변.
- `Main.java`: `window.setEffect(new MosaicEffect(...))` → `window.selectEffect(2)`(기본은 계속 모자이크, 제목 "Converter - 모자이크"). 불필요해진 MosaicEffect import 제거. 훅 순서 불변.
