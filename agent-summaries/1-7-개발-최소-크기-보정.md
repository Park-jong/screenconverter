# 1-7 개발: 최소 크기 보정 (code-writer 보고, 메인 에이전트가 대신 저장)

`mvn -B package` BUILD SUCCESS, 신규 JUnit 3개 포함 테스트 통과. 창 4초 실행 시 예외 로그 없음, 이후 java 프로세스 종료(남은 것 없음). 최소 크기에서 실제 캡처 영역이 320x180 이상인지는 실측하지 않고 단위 테스트로만 확인.

## 변경
- 신규 `ui/MinimumWindowSize.java`: 순수 함수 `compute(frameInsets, menuWidth, captureInsets, targetCapture)` — 프레임 insets(OS 테두리·제목줄) + 메뉴 폭 + 캡처 패널 border insets + 목표 캡처 영역을 더해 바깥 창 크기 반환.
- 신규 `test/.../MinimumWindowSizeTest.java`: 3개 테스트(일반 insets, insets 0, 메뉴 폭 변화 추종).
- `OverlayWindow.java`: 생성자의 `setMinimumSize(400,250)`과 `MIN_W`/`MIN_H` 제거. `MIN_CAPTURE`(320x180), `INITIAL_SIZE`(640x360) 상수 추가. MenuPanel을 필드 `menu`로 승격. `onShown()` 맨 앞에서 `applyMinimumSize()` 호출 → `getInsets()`, `menu.getPreferredSize().width`, `content.getInsets()`, `MIN_CAPTURE`로 `compute` 후 `setMinimumSize`. 메뉴 폭 180 하드코딩 중복 없음.
- `MenuPanel.java` 미수정.

예상 최소 창(insets 가로 약 16, 세로 약 39+8 가정): 약 518x229. 초기 640x360이 더 커서 조정 불필요.
미변경: 장식 설정, captureOnce, 훅 구조, closeApp, 둥근 모서리 처리, JNA.
