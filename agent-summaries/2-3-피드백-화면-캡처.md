## code-writer 피드백
2단계 수정 요구 없음. 3단계에는 `captureOnce` 구조와 `onShown` 호출 순서를 유지할 것. 화면 밖 rect 처리와 `createMultiResolutionScreenCapture` 전환 검토는 5단계.

## 3단계 주의점
- **HWND**: `onShown()`의 shownHook 안에서 획득(setVisible 이후). `Native.getComponentPointer(window)` → `new WinDef.HWND(p)`, null이면 실패 처리. 창 재생성(setUndecorated, dispose 후 재표시)을 하면 HWND가 바뀌어 affinity가 사라지므로 재생성 금지.
- **win32 패키지**: `DisplayAffinity` 인터페이스(`boolean excludeFromCapture(Component)`) + JNA 구현체 한 파일에 가둠. 다른 패키지는 JNA 타입 import 금지. JNA 5.14.0, `Native.load("user32", ..., W32APIOptions.DEFAULT_OPTIONS)`. `SetWindowDisplayAffinity(HWND, int)`, `GetWindowDisplayAffinity(HWND, IntByReference)`. 상수 WDA_NONE=0x0, WDA_MONITOR=0x1, WDA_EXCLUDEFROMCAPTURE=0x11. 실패 시 GetLastError 기록. UnsatisfiedLinkError·비 Windows는 catch해 false 반환. 호출 후 Get으로 0x11 되읽어 확인.
- **핵심 불확실성**: `Robot.createScreenCapture`(GDI BitBlt 기반)가 WDA_EXCLUDEFROMCAPTURE 창을 제외하는지는 확정할 수 없음 → 반드시 실측. 제외되면 그 자리는 검게 나오지 않고 뒤쪽 화면이 나옴(WDA_MONITOR는 검게 나옴). 0x11은 Windows 10 2004(19041) 이상에서만 지원(현재 Win11 26200 해당), 이전 버전은 실패하거나 검게 나옴. 원격 데스크톱·DWM 합성 꺼진 환경은 다를 수 있음.
- **검증 방법**: 2-2의 패턴 JFrame 하네스를 재사용하되 투명도 0 래핑 ScreenGrabber를 제거하고 순수 RobotScreenGrabber 사용. 겹침 영역 전수 비교 bad=0, 오버레이 내부색 (40,40,40)·테두리색 (200,200,200)이 하나도 없어야 함(테두리 자리도 뒤쪽 패턴). 양성/음성 대조(affinity 미적용 시 FAIL, 적용 시 PASS). 캡처 루프 가동 상태에서 무한 반복 없이 패턴만 보이는지, 이동·리사이즈 후에도 유지되는지, `java -jar`(onShown 포함) 종료 코드 0·stderr 비어 있음.
- **대체안**: ① 캡처 순간에만 창 숨기기(`captureOnce` 한 곳에서만. 깜빡임 때문에 완료 기준 충족이 어려움) ② Windows Graphics Capture / DXGI Desktop Duplication(WinRT/COM 직접 호출 또는 네이티브 헬퍼 필요, 비용 큼, 마지막 수단). Win11에서는 필요할 가능성 낮음.
- 3단계 완료 시 `captureOnce`의 "stage 3 hide/exclude point" 주석과 ROADMAP 진행표·위험도 표 갱신. fat jar에 JNA 네이티브(jnidispatch) 포함 여부는 7단계에서 확인.
