# 4-6 피드백: 흑백 효과와 전환키 (feedback-synthesizer 보고, 메인 에이전트가 대신 저장)

## 판정: 흑백 단계(4-4~4-5) 완료
ROADMAP 4′ 흑백 항목(밝기 `0.299R+0.587G+0.114B`, 옵션 임계값 2색), 전환키·레지스트리, 회귀 항목 모두 충족. 증거: 정수식 대 BigDecimal 16,777,216 조합(b 5 간격 샘플링 + 경계 후보, mismatch 0 — "전 조합"이라는 표현은 엄밀히는 샘플링 포함), 통합 28케이스 12,726,176픽셀 bad=0, 음성 대조 FAIL, Robot 키 입력(인-프로세스 + 별도 jar), 동적 267프레임 — 강함. 육안은 약함(CapturePanel.image 저장본뿐, DWM 합성 미확인). 남는 공백: DWM 육안, DPI 125/150%(5단계), 단일 모니터·배율 100%, 3단계 파일 diff(git 없음), 포커스 없을 때 키 동작, **사용자 육안 확인(4′ 완료 기준에 포함)**.

## 낮음/정보 처리
- **(a) double 식과 정수식 3,464조합 1 차이**: 조치 불필요 — 정수식이 정확. 다음 코드 수정 때 `GrayscaleEffect` 주석에 한 줄 추가("double 식 floor(0.299R+...+0.5)는 .5 경계 3,464조합에서 부동소수 오차로 1 낮게 나오므로 정수식이 기준 — 4-5 전수 검증")하고, 기존 주석의 소수 값이 "+500 이전 값"이라 손계산과 달라 보이는 문구도 정리. **도트화도 정수 연산만 사용**(팔레트 거리·명도).
- **(b) IdentityEffect 1프레임 15.6ms**: `getRGB`로 int[] 생성 후 `setRGB`로 복사 = 두 번 복사. 현재 구조(Robot이 호출마다 새 이미지 반환, 워커는 입력을 다시 쓰지 않음)에서는 입력 그대로 반환해도 실제 위험은 없으나 Effect 계약("입력 불변, 새 이미지 반환")과 충돌하고 5단계의 버퍼 재사용/더블 버퍼링과 충돌, 타입(TYPE_INT_RGB) 보장도 깨질 수 있음. **지금 바꾸지 않고 5단계 배정**: 우선 `src.getType()==TYPE_INT_RGB`일 때 `DataBufferInt` 배열을 `System.arraycopy`로 직접 복사(계약 유지, 낮은 위험). 계약 변경안은 이미지 재사용 설계와 함께 결정. 도트화·ASCII 구현자는 모자이크처럼 `DataBufferInt` 직접 접근 사용.
- **(c) 숫자 키 포커스 문제**: ESC 이월(3-3 (c))과 뿌리 같음(`WHEN_IN_FOCUSED_WINDOW`). **6단계 배정** — 결정 사항: (1) 창 클릭 시 포커스(현재 동작, 문서화) vs (2) 전역 키 훅(JNA `RegisterHotKey`/`SetWindowsHookEx`, 다른 앱 입력과 충돌 가능, 사용자 요구 확인 후). 지금은 README/`selectEffect` 주석에 "창을 한 번 클릭한 뒤 숫자 키 사용" 기록.
- **(d) CPU 효과별 차이**: 모자이크 10.4% / 재전환 7.2% 차이는 측정 잡음 범위(8초 평균 1회). 효과별 중앙값이 거의 같아 비용 대부분은 캡처와 `getRGB`. 조치 없음, 5단계에서 ASCII 기준으로 반복 측정(분산 포함).

## 픽셀 도트화(4-7~4-9) 주의점
- **구조**: 파라미터화된 단일 `PixelDotEffect(int blockSize, Palette palette, boolean gridLines)`. 처리 순서 **블록 평균 → 팔레트 양자화 → 격자**, 한 패스. 별도 효과로 연쇄하면 이미지가 두 번 만들어짐. `Palette`는 작은 클래스(NONE, FIXED(int[] rgb)), 고정 팔레트 상수 `GAMEBOY_4`(4색), `EGA_16` 등. 생성자 검증은 `MosaicEffect` 방식(IAE, 클램프 없음) — 팔레트 null·0색 거부. 블록 평균 코드는 처음엔 복사해 쓰고 테스트 확보 후 정리(모자이크 회귀 위험). effect 패키지 Swing/JNA/AWT 컴포넌트 import 금지.
- **양자화**: RGB 유클리드 **제곱 정수 거리**, 동점은 **팔레트에서 앞선 색**(독립 구현 비교용으로 명세에 박을 것). 가중 거리·명도 기반은 이번 범위 밖. **임의 N색 자동 팔레트(median cut/k-means)는 이번 범위 제외** — 무겁고 프레임마다 팔레트가 흔들려 깜빡임. 사용자의 "예: 16색"은 **고정 16색 팔레트**로 만족, "자동 팔레트는 후속"을 문서에 명시(필요 시 한 번 계산해 고정하거나 느린 이동 평균으로 안정화). 채널당 레벨 수 줄이기(예: 채널당 4레벨 = 64색)는 O(1)이고 검색이 필요 없는 선택 대안.
- **디더링**: 이번 범위 제외(블록 평균 후 매핑 구조와 어울리지 않고 테스트 복잡). 후속 메모만(블록 인덱스 기준 Bayer 임계값을 평균색에 더한 뒤 양자화 — 정수 연산 가능).
- **격자선**: 양자화 후 블록 **왼쪽·위쪽 1px**를 고정 어두운 색 하나로(부분 블록에도 자연스럽게 적용). 격자 색은 **팔레트 외 색 허용, 팔레트 검사에서 격자 위치 제외**. 원점은 모자이크와 같이 이미지 (0,0). **`gridLines`가 켜지면 `blockSize >= 4` 요구, 아니면 생성자 IAE**(조용히 끄지 않음). 기본 블록 8~10px. 격자 켬/끔 결과는 격자 위치 이외 동일해야 함(검사 포인트).
- **EffectRegistry 번호**: 1~4 사용 중, 도트화는 5부터. 숫자 키는 1~9만 → 4′ 동안은 **대표 변형만 등록해 총 9개 이내 유지**, 조합은 6단계 UI 옵션. `defaults()`에 한 줄씩 추가하되 **`EffectRegistryTest`의 미등록 번호 기대값(현재 5, 9)을 같이 갱신**, 4-5 키 입력 검증의 "5는 무시"도 도트화 추가 후 무효 → 미등록 번호를 새로 고를 것.
- **검증 방법**: 4-5 통합 하네스에 도트화 추가, 독립 구현 기대값(정수, 동점 규칙 동일) 전수 비교(6개 크기 + 최대화, 홀수·최소 크기). 팔레트 속성 검사(격자 끔은 전 픽셀이 팔레트 안, 격자 켬은 격자 위치 제외), 격자 위치 검사(경계 행/열이 격자 색, 그 외 블록 내부 단색, 가장자리·부분 블록 포함), **팔레트 끔 + 격자 끔이면 `MosaicEffect`와 동일** 교차 검증, 단위 손계산(게임보이 4색의 순흑·순백·중간 회색·순빨강, 동점 거리 케이스 하나 이상), 음성 대조(모자이크로 바꾸면 팔레트·격자 검사 FAIL, 팔레트를 바꾸면 기대값 FAIL), 전환 회귀·동적 프레임 재사용(하네스의 초기 효과 번호는 레지스트리에서 읽어 오기). 육안은 격자 켬/끔 × 팔레트 켬/끔 4조합 저장. 성능은 1738x1007 중앙값을 모자이크(약 6~7ms)와 비교.

## 이월 정리
5단계: IdentityEffect 복사 개선(래스터 직접 복사 우선), CPU 비교 반복 측정. 6단계: 포커스 없는 키 입력(ESC·숫자 키), 효과 9개 초과 시 선택 UI. 사용자 육안 확인(4′ 완료 기준)은 도트화까지 구현한 뒤 한꺼번에 요청 가능.
