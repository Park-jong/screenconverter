## 빌드·코드 리뷰
- `mvn -B clean package` BUILD SUCCESS, 테스트 46개 통과.
- **Palette**: GAMEBOY_4·EGA_16이 요청한 값·순서와 같음(`Arrays.equals` true). `fixed()`·`colors()` 모두 방어적 복사(변경 시도에도 상수 불변). 동점은 strict `<`라 앞선 색 승, 팔레트 순서를 뒤집으면 결과가 따라 바뀜. 거리는 int 최대 195075로 오버플로 없음. 독립 구현과 GB·EGA 각각 16,777,216색 전수 비교 불일치 0.
- **PixelDotEffect의 DataBufferInt 직접 접근**: `>>16, >>8, &0xFF` 마스크만 써서 ARGB 알파가 평균에 섞이지 않음(알파 0/0x7F/0xFF, 같은 RGB에 알파만 다른 입력 결과 동일). "촘촘한 레이아웃" 판정: INT_RGB/INT_ARGB, 뱅크 1개, `getOffset()==0`, scanlineStride==w, sampleModelTranslate 0/0, 배열 길이 ≥ w*h일 때만 직접 접근, 그 외는 `getRGB` 폴백. getSubimage 11종(x/y 오프셋, 좁은 폭, 1x1, 하위의 하위), stride 37 래스터, 오프셋 11짜리 ARGB 래스터, INT_ARGB_PRE, INT_BGR, 3BYTE_BGR, 4BYTE_ABGR, 565, GRAY, INDEXED 모두 정확. 입력 불변, 출력 TYPE_INT_RGB·알파 0xFF·크기 일치. 부분 블록 평균은 실제 count 분모와 `(sum+n/2)/n`. 격자는 블록 왼쪽 열·위쪽 행 1px, 부분 블록에도 칠하고 경계를 넘지 않음. 생성자 검증 5종 IAE(blockSize 1/0/-5, 격자+블록 3, 팔레트 null), 경계 (2, NONE, 격자 없음)·(4, NONE, 격자)는 허용, `apply(null)`은 NPE.
- 독립 레퍼런스 비교(`w\U.java`): 9종 이미지 타입 × 12개 크기 × 11개 설정 + 서브이미지 + 무작위 300건 = 1561건 FAILS=0.
- import·등록·불변: effect 패키지 import는 `java.awt.image.*`·`java.util.*`뿐. EffectRegistry 5=도트 16색, 6=도트 게임보이, 7=도트 격자, 8=도트 16색+격자(블록 8), 9 비어 있음(selectEffect(9) 무시 실측). OverlayWindow·Main 15:37, MosaicEffect 15:21, win32 15:13으로 4-7 변경 시각(15:53) 이전.

## 단위 테스트 재검토
4x4 손계산 재확인: 평균 (128,141,40), AA5500까지 42²+56²+40²=6500, 555555까지 43²+56²+45²=7010 → AA5500. 동점 케이스는 팔레트 순서를 바꿔 앞선 색 선택을 검증하므로 순환 아님. NONE+격자 off == MosaicEffect 테스트는 기존 구현과의 교차 검증. 10x7 부분 블록 테스트도 분모를 테스트 안에서 `(sum+3)/6`으로 직접 계산해 순환 아님.
